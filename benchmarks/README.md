# Cairn benchmarks

Reproducible, offline benchmarks for the Cairn runtime. Every script is
deterministic (scripted models, hand-written datasets, no network), writes a
JSON result and a Markdown report into `benchmarks/results/`, and stamps each
result with the git commit, Python version and platform so numbers can be
compared across machines and commits.

## How to run

```sh
# one at a time (writes results/<name>.json and results/<name>.md)
PYTHONPATH=src python benchmarks/injection_suite.py
PYTHONPATH=src python benchmarks/runtime_overhead.py
PYTHONPATH=src python benchmarks/retrieval_quality.py
PYTHONPATH=src python benchmarks/recovery.py
```

The scripts add `src/` to `sys.path` themselves, so `PYTHONPATH=src` is
optional but harmless. No arguments are required.

Datasets live in `benchmarks/datasets/` and are regenerated by their
`_build_*.py` scripts; each dataset is versioned JSONL with a content hash that
every result records, so a result is always tied to the exact data that
produced it.

Result files contain only measured values. Timing numbers depend on the
machine (recorded in each file's header); correctness and quality numbers
(attack success, recall, recovery) are machine independent.

## Benchmarks

### `injection_suite.py` (prompt-injection defense)

Dataset: `datasets/injection_cases.jsonl` (26 attacks + 4 benign controls
across five untrusted channels: web fetch, retrieved document, MCP-like tool
output, email body, file content; five attack goals: exfiltrate, write file,
execute command, send payment, forward secret). The model is a **fully
compromised** `ScriptedProvider` that always obeys the injected instruction and
extracts the attacker's target into the sensitive argument. Each case runs
with the policy disabled (baseline), enabled with an auto-rejecting operator,
and in strict "no human available" mode. An attack succeeds only when the
privileged sink actually executes with the attacker's value and without an
approval. Report: `results/injection_suite.md`.

Measured (this machine): policy off lets **100%** of the 26 attacks through;
policy on and strict both block **26/26 (0% success)** across every channel and
every goal, while benign tasks still complete at **100%**. Policy-on requests
one approval per attack (which the operator rejects); strict mode denies
outright with no approval.

### `runtime_overhead.py` (runtime cost)

Measures journal append throughput (in-memory and SQLite), executor overhead
per node for sequential and parallel plans of trivial tools, replay speed, and
fork reuse ratio. Uses `time.perf_counter` over several repetitions and reports
mean / p50 / p95. Report: `results/runtime_overhead.md`.

Measured (this machine, 4 CPUs): in-memory journal ~68k events/s, SQLite ~30k
events/s; executor overhead ~0.4 to 0.7 ms per node; replay ~1.7k to 2.4k
reused effects/s; forking a chain reuses all upstream effects when the last
node is patched and none when the first is patched.

### `retrieval_quality.py` (retrieval)

Datasets: `datasets/retrieval_corpus.jsonl` (40 short technical docs) and
`datasets/retrieval_queries.jsonl` (30 paraphrased queries with graded
relevance labels). Compares lexical (BM25), dense (`HashingEmbedder`) and
hybrid (RRF) on recall@5, MRR and nDCG@5. Report:
`results/retrieval_quality.md`.

**Honesty note:** `HashingEmbedder` is feature hashing over stemmed n-grams and
character trigrams. It is lexical-ish, not a neural semantic model, so "dense"
here measures morphological and n-gram overlap rather than deep meaning. The
queries are paraphrased to reduce exact word overlap, which is the hardest
setting for all three modes. Swap in a real embedding model
(`ProviderEmbedder`) to measure semantic retrieval; the harness is unchanged.

Measured (this machine): lexical recall@5 0.78 / MRR 1.00 / nDCG@5 0.88, dense
0.73 / 0.96 / 0.83, hybrid 0.77 / 1.00 / 0.87. On this lexical-ish embedder and
these paraphrased queries, BM25 leads; hybrid matches BM25 on MRR. This is
expected and is the point of the honesty note.

### `recovery.py` (fault injection and recovery)

Injects deterministic transient faults (scripted model `fail_times`, a tool
that fails its first N calls) and pairs each with a recovery policy (retries,
fallbacks, `on_error=default`), comparing against no-policy controls. Measures
recovery success rate and extra attempts. Report: `results/recovery.md`.

Measured (this machine): no-retry controls fail at 0%; retry recovers 2 faults
at 100% with 2 extra attempts; retries exhausted by 5 faults fail at 0%;
`on_error=default` and a model fallback both recover at 100%. Recovery rate
where a policy should recover: **100%**.

## Notes

- No file in this directory, including generated results and datasets, contains
  an em dash (U+2014); `_common.py` refuses to write results that do.
- The attack dataset uses only fake, non-routable identifiers
  (`*.attacker.test`, `acct-fake-*`). The payloads are security test fixtures,
  not real attacks.
